Configurar Supabase para FOSE Unified

Guia paso a paso para activar el backend en la nube

1

Crear cuenta en Supabase

  1. Abra su navegador y vaya a https://supabase.com
  2. Haga clic en el boton verde "Start your project"
  3. Registrese con su cuenta de GitHub o con correo electronico y contrasena
Recomendacion: Si tiene cuenta de GitHub, use esa opcion. Es mas rapido y no necesita verificar correo.
2

Crear un nuevo proyecto

  1. Una vez dentro, haga clic en "New Project"
  2. Llene los campos:
    • Organization: Seleccione la que aparece (o cree una nueva)
    • Name: Escriba fose-presupuesto
    • Database Password: Escriba una contrasena segura y guardela en un lugar seguro
    • Region: Seleccione South America (Sao Paulo)
    • Plan: Deje en Free (gratis)
  3. Haga clic en "Create new project"
  4. Espere aproximadamente 2 minutos mientras se crea el proyecto
Importante: Guarde la contrasena de la base de datos. La necesitara si quiere conectarse directamente a PostgreSQL.
3

Copiar las credenciales de la API

  1. En el menu lateral izquierdo, haga clic en el icono de engranaje (Project Settings)
  2. Luego haga clic en "API" (bajo Configuration)
  3. Copie estos dos valores y guardelos:
    • Project URL: Algo como https://abcdefg.supabase.co
    • anon public key: Una cadena larga que empieza con eyJ...
Consejo: Copie cada valor y peguelo en un bloc de notas temporal. Los necesitara en el Paso 6.
4

Crear las tablas de la base de datos

  1. En el menu lateral, haga clic en "SQL Editor" (icono de codigo)
  2. Se abre un editor. Borre todo lo que haya ahi
  3. Copie TODO el siguiente codigo SQL y peguelo en el editor:
-- ===================================================== -- FOSE Unified - Esquema de Base de Datos para Supabase -- ===================================================== -- 1. Tabla de perfiles (extiende auth.users) CREATE TABLE public.profiles ( id UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY, email TEXT, nombre TEXT, created_at TIMESTAMPTZ DEFAULT now() ); -- 2. Tabla de instituciones (datos como JSONB) CREATE TABLE public.instituciones ( id TEXT PRIMARY KEY, nombre TEXT NOT NULL, data JSONB NOT NULL DEFAULT '{}'::jsonb, owner_id UUID REFERENCES public.profiles(id), updated_at TIMESTAMPTZ DEFAULT now(), created_at TIMESTAMPTZ DEFAULT now() ); -- 3. Acceso multi-usuario a instituciones CREATE TABLE public.user_instituciones ( user_id UUID REFERENCES public.profiles(id) ON DELETE CASCADE, inst_id TEXT REFERENCES public.instituciones(id) ON DELETE CASCADE, role TEXT DEFAULT 'editor' CHECK (role IN ('owner','editor','viewer')), created_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY (user_id, inst_id) ); -- 4. Directorio de personas (por usuario) CREATE TABLE public.personas ( id TEXT PRIMARY KEY, owner_id UUID REFERENCES public.profiles(id) ON DELETE CASCADE, data JSONB NOT NULL DEFAULT '{}'::jsonb, updated_at TIMESTAMPTZ DEFAULT now() ); -- 5. Metadatos de la app por usuario CREATE TABLE public.app_meta ( user_id UUID REFERENCES public.profiles(id) ON DELETE CASCADE PRIMARY KEY, active_inst_id TEXT, cambios INTEGER DEFAULT 0, updated_at TIMESTAMPTZ DEFAULT now() ); -- ===================================================== -- SEGURIDAD: Row Level Security (RLS) -- ===================================================== ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY; ALTER TABLE public.instituciones ENABLE ROW LEVEL SECURITY; ALTER TABLE public.user_instituciones ENABLE ROW LEVEL SECURITY; ALTER TABLE public.personas ENABLE ROW LEVEL SECURITY; ALTER TABLE public.app_meta ENABLE ROW LEVEL SECURITY; -- Politicas para profiles CREATE POLICY "Users read own profile" ON public.profiles FOR SELECT USING (auth.uid() = id); CREATE POLICY "Users update own profile" ON public.profiles FOR UPDATE USING (auth.uid() = id); CREATE POLICY "Users insert own profile" ON public.profiles FOR INSERT WITH CHECK (auth.uid() = id); -- Politicas para instituciones CREATE POLICY "Users read their institutions" ON public.instituciones FOR SELECT USING ( EXISTS ( SELECT 1 FROM public.user_instituciones WHERE user_id = auth.uid() AND inst_id = instituciones.id ) ); CREATE POLICY "Users update their institutions" ON public.instituciones FOR UPDATE USING ( EXISTS ( SELECT 1 FROM public.user_instituciones WHERE user_id = auth.uid() AND inst_id = instituciones.id AND role IN ('owner','editor') ) ); CREATE POLICY "Authenticated users create institutions" ON public.instituciones FOR INSERT WITH CHECK (auth.uid() = owner_id); CREATE POLICY "Owners delete institutions" ON public.instituciones FOR DELETE USING (owner_id = auth.uid()); -- Politicas para user_instituciones CREATE POLICY "Users see own access" ON public.user_instituciones FOR SELECT USING (user_id = auth.uid()); CREATE POLICY "Owners manage access" ON public.user_instituciones FOR INSERT WITH CHECK ( auth.uid() = user_id OR EXISTS ( SELECT 1 FROM public.user_instituciones ui WHERE ui.user_id = auth.uid() AND ui.inst_id = user_instituciones.inst_id AND ui.role = 'owner' ) ); CREATE POLICY "Owners remove access" ON public.user_instituciones FOR DELETE USING ( user_id = auth.uid() OR EXISTS ( SELECT 1 FROM public.user_instituciones ui WHERE ui.user_id = auth.uid() AND ui.inst_id = user_instituciones.inst_id AND ui.role = 'owner' ) ); -- Politicas para personas CREATE POLICY "Users read own personas" ON public.personas FOR SELECT USING (owner_id = auth.uid()); CREATE POLICY "Users insert own personas" ON public.personas FOR INSERT WITH CHECK (owner_id = auth.uid()); CREATE POLICY "Users update own personas" ON public.personas FOR UPDATE USING (owner_id = auth.uid()); CREATE POLICY "Users delete own personas" ON public.personas FOR DELETE USING (owner_id = auth.uid()); -- Politicas para app_meta CREATE POLICY "Users read own meta" ON public.app_meta FOR SELECT USING (user_id = auth.uid()); CREATE POLICY "Users insert own meta" ON public.app_meta FOR INSERT WITH CHECK (user_id = auth.uid()); CREATE POLICY "Users update own meta" ON public.app_meta FOR UPDATE USING (user_id = auth.uid()); -- ===================================================== -- TRIGGERS AUTOMATICOS -- ===================================================== -- Trigger: Crear perfil y app_meta al registrarse CREATE OR REPLACE FUNCTION public.handle_new_user() RETURNS TRIGGER AS $$ BEGIN INSERT INTO public.profiles (id, email, nombre) VALUES (NEW.id, NEW.email, COALESCE(NEW.raw_user_meta_data->>'nombre', '')); INSERT INTO public.app_meta (user_id) VALUES (NEW.id); RETURN NEW; END; $$ LANGUAGE plpgsql SECURITY DEFINER; CREATE TRIGGER on_auth_user_created AFTER INSERT ON auth.users FOR EACH ROW EXECUTE FUNCTION public.handle_new_user(); -- Trigger: Actualizar updated_at automaticamente CREATE OR REPLACE FUNCTION public.update_updated_at() RETURNS TRIGGER AS $$ BEGIN NEW.updated_at = now(); RETURN NEW; END; $$ LANGUAGE plpgsql; CREATE TRIGGER tr_instituciones_updated BEFORE UPDATE ON public.instituciones FOR EACH ROW EXECUTE FUNCTION public.update_updated_at(); CREATE TRIGGER tr_personas_updated BEFORE UPDATE ON public.personas FOR EACH ROW EXECUTE FUNCTION public.update_updated_at(); CREATE TRIGGER tr_app_meta_updated BEFORE UPDATE ON public.app_meta FOR EACH ROW EXECUTE FUNCTION public.update_updated_at();
  1. Haga clic en el boton "Run" (o presione Ctrl+Enter)
  2. Debe aparecer un mensaje verde: "Success. No rows returned"
Si da error: Verifique que copio TODO el codigo SQL completo, desde la primera linea hasta la ultima.
5

Desactivar confirmacion de correo

  1. En el menu lateral, vaya a Authentication (icono de persona)
  2. Haga clic en la pestana "Providers"
  3. Haga clic en "Email" para expandirlo
  4. Desactive la opcion "Confirm email"
  5. Haga clic en "Save"
Por que: Si deja activa la confirmacion, los usuarios tendran que verificar su correo antes de poder usar la app. Desactivandola es mas practico.
6

Configurar la app FOSE con sus credenciales

  1. Abra el archivo js/supabase.js de su app FOSE con un editor de texto
  2. En las primeras lineas, encontrara:
    const SUPABASE_URL = 'https://TU-PROYECTO.supabase.co'; const SUPABASE_ANON_KEY = 'TU-ANON-KEY-AQUI';
  3. Reemplace https://TU-PROYECTO.supabase.co con su Project URL (del Paso 3)
  4. Reemplace TU-ANON-KEY-AQUI con su anon public key (del Paso 3)
  5. Guarde el archivo
Cuidado: No borre las comillas simples. El resultado debe verse asi:
const SUPABASE_URL = 'https://abcdefg.supabase.co';
7

Abrir la app y registrarse

  1. Abra index.html en su navegador (Edge recomendado)
  2. Aparecera la pantalla de inicio de sesion
  3. Haga clic en la pestana "Registrarse"
  4. Ingrese:
    • Nombre: Su nombre completo
    • Correo: Su correo electronico
    • Contrasena: Minimo 6 caracteres
  5. Haga clic en "Crear cuenta"
  6. La app cargara y estara lista para usar
Listo! A partir de ahora, sus datos se guardan automaticamente en la nube. Puede abrir la app en cualquier navegador, iniciar sesion con el mismo correo y ver todos sus datos.
8

Migrar datos existentes (opcional)

Si ya tenia datos en la app (antes de Supabase), la app detectara automaticamente sus datos locales y le preguntara si desea subirlos al servidor.

  1. Al iniciar sesion por primera vez, vera el mensaje: "Se encontraron datos locales"
  2. Haga clic en "Subir al servidor"
  3. Espere a que se complete la migracion
  4. Sus datos quedaran en la nube
